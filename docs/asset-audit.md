# Production asset audit

The `asset-audit` playtest inspects original production resources and native menu controls. It can run headless for resource/geometry/layout validation; graphical runs additionally capture `asset-audit-inspection-gallery.png`. That labeled gallery is an inspection viewport containing production meshes and materials, not a recorded match or replacement menu.

The audit loads both bundled fonts directly, verifies their embedded font data, ordinary UI letters/digits and measurable text, then checks glyph support for actual visible menu text. It loads the application icon through Godot's resource importer. Resource loading respects exported resource remaps, so the check does not depend on original source files surviving export.

Geometry coverage includes all eight suit materials on the production player, normal/red/remote/pumped bombs, all eleven pickup kinds (with their plate, scale and bob clearance), and the actual stone/masonry/bedrock/water shader materials. Each mesh needs nonempty surfaces, finite vertices/normals, noncollapsed finite bounds, finite node transforms and a readable material. Shader source must exist; graphical rendering is the separate compilation/rendering witness. Negative fixtures verify rejection of a missing resource, an empty mesh and nonfinite vertex data, without submitting invalid geometry to the renderer.

The real Modes, Roster, Setup, Online and Controls screens are opened through product navigation. Graphical runs inspect 1280×800 and 1280×720; headless runs inspect the current logical viewport and perform no native window resize. Visible native buttons and text fields must fit the viewport, and their actual visible text must have supported glyphs. Existing model-profile tests retain detailed helmet/face topology and silhouette checks; existing menu tests retain keyboard, mouse and controller interaction checks.

This audit catches missing assets, silent font fallback, invalid generated geometry and controls escaping the supported viewport. A passing headless audit does not establish shader compilation, visual appeal, text contrast, real GPU performance, or controller behavior. Keep the graphical gallery, model profiles and real interaction scenarios in the broader verification run.
