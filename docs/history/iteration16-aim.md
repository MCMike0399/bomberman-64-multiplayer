# Deliberate throw authority

Holding Aim while carrying a bomb plants the carrier. Horizontal input turns the stored direction clockwise for right and counterclockwise for left (+X right, +Z down in the arena top view); up extends range and down shortens it. Turn speed is bounded to 120 degrees/second and range adjustment to 3 cells/second, with the same normalized input and clock for keyboards and controllers. Each axis starts at 25% of that rate and ramps to full speed after 0.30 seconds of sustained input in the same direction. Neutral, reversal, leaving the stance or a new carry resets that axis to the fine starting rate. Short keyboard taps therefore move about one degree or 0.025 cells per authority tick; partial controller input scales that rate proportionally. Neutral input retains intent. Releasing Aim restores movement while retaining the direction, so a carrier can reposition and strafe before throwing. Throw, drop, knockdown and a new carry clear that intent.

A deliberate lob has a nominal level-ground range of 2–9 cells, initially 4.5, and a fixed vertical launch speed of 8.5. Its range is calibrated against the authority's discrete gravity integration rather than a continuous approximation. Elevation changes the actual endpoint; the high arc can reach the temple's fourth tier. Pumping changes blast charge without changing a deliberately chosen range. Ordinary throws retain the existing launch rule. These speeds and ranges are project tuning, not measured original-game physics.

`PlayerInput` and the owned game input JSON append an optional `Aim` / `aim` boolean; omitted values preserve old clients. `aiming`, `aimSet`, `aimX`, `aimZ` and `aimRange` snapshots carry accepted authority intent. No kernel contract or source changes are required. Clients should construct deliberate launch velocity with `BombThrowRules.AimedVelocity`, never infer it from stick strength.

`BombThrowRules.AdvanceStatic` and `Project` share a radius-0.35 swept footprint, with horizontal samples at most 0.1 units apart. Both consume the same terrain surface, cell-kind and current-cover queries. Pillar and cover tops are 0.9 and 0.61 gameplay units above the surface, matching the scaled scenery. Low side impacts stop horizontal velocity, then gravity and the fuse continue; high lobs clear low cover. A terrain ledge behind the direction of travel does not catch the trailing footprint when a bomb descends off land into water. Descending onto a solid top rests there with an exact `LandingY`. Removing that support starts a gravity fall from the previous height. Pickup, kick and throw clear the stored support.

The preview must pass ground surface (including the actual water/void plane), cell kind and cover bits to `Project`; the old conservative obstruction callback should be `_ => false` when using these queries. After a static stop, the projection continues down to the actual endpoint and reports `Obstructed`; fuse expiry still takes precedence. An optional accepted `waterLevel` clips the guide at the current flood plane even over submerged floor; future water movement remains advisory. Player contacts, moving bombs and future map changes remain advisory uncertainties. The authority grants no owner immunity or target assistance.
